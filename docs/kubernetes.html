Path B · Kubernetes · us1

Deploy the OpenTelemetry Demo to Kubernetes

The same demo shown to the customer: about twenty microservices already instrumented with OpenTelemetry, sending OTLP to an in-cluster Collector that tags every signal and exports to Splunk Observability Cloud.

About 40 minutes · a Kubernetes cluster with kubectl and helm · an ingest token

How this relates to Path A

This is the Collector design from Path A, running as a Kubernetes agent: the apps carry no token, and only the Collector holds it. To compare it with SDK-direct export, use Path A.

Based on the OpenTelemetry Kubernetes Demo guide

The steps and commands follow the OpenTelemetry Kubernetes Demo workshop guide, adapted so you can run it on your own cluster. That guide assumes a prepared workshop host where REALM, ACCESS_TOKEN and INSTANCE are already set. Here you set them yourself in Step 1.

Step 1~5 min

Pre-flight

You need a Kubernetes cluster you can reach with kubectl, plus helm and git. The workshop used a three-node k3d cluster; kind, minikube or a cloud cluster also work. The full demo needs roughly 9 to 10 GB of memory. With about 8 GB (for example minikube on Docker Desktop at its default size), use lite mode in Step 3. Check the OpenTelemetry Demo requirements for details.

bash
kubectl get nodes
expected output
NAME                            STATUS   ROLES                  AGE   VERSION
k3d-shw-455e-cluster-agent-0    Ready    <none>                 5d    v1.33.4+k3s1
k3d-shw-455e-cluster-agent-1    Ready    <none>                 5d    v1.33.4+k3s1
k3d-shw-455e-cluster-server-0   Ready    control-plane,master   5d    v1.33.4+k3s1

Set three variables, and where the token goes

The install command in Step 4 reads three shell variables. They live only in your terminal session, so there is no file to leak.

bash
export REALM=us1
read -rs ACCESS_TOKEN && export ACCESS_TOKEN     # paste your INGEST token, press Enter (it is not echoed)
export INSTANCE=northstar-01                      # short id: lowercase letters, digits, hyphens
bash
echo "REALM=$REALM"
[ -n "$ACCESS_TOKEN" ] && echo "TOKEN: set" || echo "TOKEN: MISSING"
echo "INSTANCE=$INSTANCE"
Key idea

INSTANCE becomes lab.id. Resource attributes on the Collector tag every signal with it, so you can filter to your demo in Observability Cloud even if other people share the org.

Token type

Use an org access token with the Ingest scope. An API-scope token returns 401 at the ingest endpoint.

Step 3~5 min

Create splunk-values.yaml

This file adds two Splunk exporters and a processor to the demo's Collector and wires them into the traces and metrics pipelines. Save it as splunk-values.yaml in the opentelemetry-demo directory.

Empty strings are intentional

Realm, token and resource attribute values are injected at install time by the --set-string flags in Step 4. You do not paste secrets into this file.

Chart version matters

This values file is written for demo chart opentelemetry-demo 0.42.x (demo 3.1.0), which uses snake_case Collector names such as otlp_http, resource_detection and span_metrics. Older chart versions use otlphttp, resourcedetection and spanmetrics. If the Collector crash-loops with references receiver "spanmetrics" which is not configured, your chart and values file are from different eras. Run helm show values open-telemetry/opentelemetry-demo and copy the component names from the opentelemetry-collector.config section.

Small cluster? Use lite mode

The full demo asks for roughly 9 to 10 GB of memory and about 30 pods. On a laptop cluster with about 8 GB, add a second values file, lite-values.yaml, that turns off Grafana, Jaeger, Prometheus, OpenSearch and the AI chatbot components and exports only to Splunk. Keep astronomy-db enabled, because product-catalog waits for it at startup. Both files are in the k8s/ folder of the lab repo.

splunk-values.yaml
opentelemetry-collector:
  config:
    exporters:
      otlp_http/signalfx:
        traces_endpoint: ""
        headers:
          X-SF-Token: ""
          Content-Type: "application/x-protobuf"
        sending_queue:
          batch: {}
      signalfx:
        realm: ""
        access_token: ""
    processors:
      resource/lab:
        attributes:
          - key: lab.id
            value: ""        # Index [0]
            action: upsert
          - key: lab.owner
            value: ""        # Index [1]
            action: upsert
          - key: k8s.cluster.name
            value: ""        # Index [2]
            action: upsert
          - key: deployment.environment
            value: ""        # Index [3]
            action: upsert
    service:
      pipelines:
        traces:
          processors: [memory_limiter, resource_detection, resource, resource/lab, transform/sanitize_spans, gen_ai_normalizer, transform/redact_sensitive_data, redaction]
          exporters: [otlp_grpc/jaeger, debug, span_metrics, otlp_http/signalfx]
        metrics:
          receivers: [otlp, kafkametrics, span_metrics, prometheus/ad]
          processors: [memory_limiter, resource_detection, resource, resource/lab]
          exporters: [otlp_http/prometheus, debug, signalfx]
        logs:
          processors: [memory_limiter, resource_detection, resource, resource/lab, transform/sanitize_logs]
          exporters: [opensearch, debug]

The attribute index in the install command refers to the position of each attribute above:

IndexKeySet at install to
[0]lab.id${INSTANCE}
[1]lab.owneryour name, no spaces
[2]k8s.cluster.name${INSTANCE}-cluster
[3]deployment.environmentk8s-workshop-${INSTANCE}

Why these endpoints: traces use the same OTLP/HTTP ingest path as Path A (/v2/trace/otlp, with the X-SF-Token header). This guide's tested config sends metrics through Splunk's signalfx exporter, which needs only the realm and token. Sending metrics as OTLP to /v2/datapoint/otlp (Path A) is also supported.

Logs stay in the demo

The logs pipeline goes to the demo's own OpenSearch and the debug exporter, not to Splunk. Splunk Log Observer is not part of this setup.

Step 4~10 min

Install

Shortcut: the lab repo script

k8s/install.sh runs this same helm upgrade --install for you. It reads SPLUNK_REALM and SPLUNK_ACCESS_TOKEN from the repo's .env, picks lite mode automatically on small clusters, and sets the environment to k8s-workshop-<INSTANCE>. Run LAB_OWNER=yourname ./k8s/install.sh.

Set lab.owner to your name

Replace <your name, no spaces> in the command below. It is how you will find your application in Observability Cloud.

bash
helm install otel-demo open-telemetry/opentelemetry-demo \
  -n otel-demo --create-namespace \
  -f splunk-values.yaml \
  --set-string "opentelemetry-collector.config.exporters.otlp_http/signalfx.traces_endpoint=https://ingest.${REALM}.signalfx.com/v2/trace/otlp" \
  --set-string "opentelemetry-collector.config.exporters.otlp_http/signalfx.headers.X-SF-Token=${ACCESS_TOKEN}" \
  --set-string "opentelemetry-collector.config.exporters.signalfx.realm=${REALM}" \
  --set-string "opentelemetry-collector.config.exporters.signalfx.access_token=${ACCESS_TOKEN}" \
  --set-string "opentelemetry-collector.config.processors.resource/lab.attributes[0].value=${INSTANCE}" \
  --set-string "opentelemetry-collector.config.processors.resource/lab.attributes[2].value=${INSTANCE}-cluster" \
  --set-string "opentelemetry-collector.config.processors.resource/lab.attributes[3].value=k8s-workshop-${INSTANCE}" \
  --set-string "opentelemetry-collector.config.processors.resource/lab.attributes[1].value=<your name, no spaces>"

The traces endpoint above uses the signalfx.com hostname that this demo was tested with. For us1 the equivalent newer hostname is ingest.us1.observability.splunkcloud.com; both are accepted.

Adapting for a customer cluster

  • Token handling. Helm records the values it was installed with in a Secret in the release namespace, so a token passed with --set-string is readable by anyone who can read Secrets there. For anything beyond a lab, load the token from a Kubernetes Secret or your secrets manager and use short-lived tokens.
  • Their own services. The demo shows the Collector side. For the customer's real workloads, point their existing OTLP exporters at the in-cluster Collector service instead of at Splunk, which keeps the token in one place. See the debrief table for the trade-offs.
  • Egress. Only the Collector pods need outbound HTTPS to ingest.<realm>.signalfx.com or ingest.<realm>.observability.splunkcloud.com.
  • Sensitive data. Add a redaction processor to the Collector before export, and agree the attribute list with the security team first.
  • Environment names. Use a clear deployment.environment per cluster, with consistent casing.

Diagnostics

Test the ingest endpoint directly

bash
curl -i -X POST "https://ingest.${REALM}.signalfx.com/v2/trace/otlp" \
  -H "X-SF-Token: ${ACCESS_TOKEN}" -H "Content-Type: application/x-protobuf"

Any HTTP response proves the network path to the endpoint works. A 401 points to the token. This sends an empty request, so a non-success status other than 401 is not necessarily a problem.

Inspect the rendered Collector config

bash
kubectl -n otel-demo get cm otel-collector-agent -o yaml | less

Confirm the Collector received the values

bash
kubectl -n otel-demo describe pod -l app.kubernetes.io/name=opentelemetry-collector | grep -E "REALM:|ACCESS_TOKEN:"

Force a Collector restart

bash
kubectl -n otel-demo delete pods -l app.kubernetes.io/name=opentelemetry-collector

Common errors

Error in Collector logsFix
references receiver "spanmetrics" which is not configuredChart and values file are from different versions. Use span_metrics on chart 0.42.x, or match every name to helm show values.
Pods stuck Pending with Insufficient memoryThe cluster is smaller than the demo needs. Use lite mode, or give the cluster more memory.
product-catalog stuck in Init:0/1It waits for astronomy-db. Do not disable that component in lite mode.
references exporter "X" which is not configuredA pipeline lists an exporter that is not defined under exporters:. Restate the chart defaults in your values file.
unknown type: "sapm"The sapm exporter was removed from contrib. Use otlp_http/signalfx for traces.
404 ... /v1/metricsWrong path for OTLP metrics. Use the signalfx exporter, or the /v2/datapoint/otlp path from Path A.
404 ... /v1/logSplunk Log Observer is not provisioned on this org. Drop the logs exporter to Splunk.
401 UnauthorizedThe token must be an Ingest-scope token.
Pods stuck PendingThe cluster is too small. Add nodes or free resources.
